## 1. Contexte

Module PrestaShop 8 de **vues éclatées OEM** (microfiches) pour motos KTM / Husqvarna / GasGas,
sur le thème `megaservice`. Arborescence front cible :

```
Moto (hub)  →  Partie (cycle | moteur)  →  Microfiche (vue éclatée + hotspots)  →  Pièce (produit PS)
```

Le **garage / sélecteur de véhicule est le périmètre d'EveryParts**, pas le nôtre : nos pages sont
joignables par URL (`id_moto`), on ne câble pas le sélecteur.

## 2. Ce qui a été livré

### 2.1 PLP moto (liste des microfiches d'une partie) — pixel-perfect

Maquette `PLP_CAT_SPAREPARTS` répliquée en réutilisant le chrome catégorie du thème
(`.ms-catalog-hero`, `.ms-catalog-context`, `.ms-catalog-layout`, `.ms-product-card`) :

- **Sidebar** : carte « Partie », filtre catégorie (checkboxes + compteurs), « Voir plus » au-delà
  de 9 items, bloc « Disponibilité » (visuel, câblage réel plus tard), « Réinitialiser ».
- **Toolbar** : compteur de résultats + **dropdown de tri client-side**
  (défaut / nom A→Z / nom Z→A / plus de pièces) — réordonne les cartes sans rechargement.
- **Breadcrumb** : ajout du niveau **Partie** après le modèle de moto.
- **Pas de pagination** — décision produit : le nombre de microfiches par moto/partie reste
  faible, tout tient sur un écran.

### 2.2 PDP microfiche — parcours panier corrigé

- Ajout au panier en **AJAX** (panneau latéral), comme le reste du site — plus de navigation
  vers la page panier.
- Bouton d'ajout affiché **uniquement si le produit est réellement commandable** ;
  quantité **bornée au stock réel** → plus d'erreur « quantité maximum ».
- Hors stock → pas d'ajout panier (**décision client**), parcours alternatif à définir.
- Breadcrumb : ajout du niveau **Partie** (dérivé de la catégorie de la microfiche).

### 2.3 URLs propres (routing)

`hookModuleRoutes` — schéma **id-based** (robuste, comme produits/catégories PS), la **partie est
un vrai niveau d'URL** :

```
/motos/{id}-{slug}              → page hub moto
/motos/{id}-{slug}/{partie}     → PLP scopée cycle|moteur
/microfiches/{id}-{slug}        → PDP microfiche
```

- Le `slug` (via `Tools::str2url`) est **cosmétique/SEO** : PS route par **id**, donc un slug
  obsolète charge quand même la bonne page.
- Slug propagé dans **tous** les `getModuleLink` (cartes PLP, carrousel lié, breadcrumbs).
- Les anciennes URLs `/module/megaservice_microfiches/...` continuent de fonctionner.

### 2.4 Page « hub moto » (Phase 1)

`/motos/{id}-{slug}` (sans partie) affiche désormais une **page composite** au lieu de toutes les
microfiches :

- Hero + bannière modèle (« Catalogue filtré sur… »)
- **3 cartes d'accès** : Partie cycle → `/cycle`, Partie moteur → `/moteur`, Powerparts
- Bloc **« Dernières microfiches »** (4 dernières de la moto)
- Bloc **« Accessoires Powerparts »** — produits de la catégorie 41, rendus avec la **miniature
  produit native** du thème (prix, badge remise, ajout panier AJAX)

Le mode PLP (avec partie) est inchangé.

### 2.5 Cards microfiche — itérations d'affichage

Plusieurs allers-retours, **état final = état d'origine** : miniature normalisée (`thumb`) +
`object-fit: contain` + ratio de base `250/171`.

- Testé : image entière (`image_full_url`) → **rejeté** (dimensions trop variables d'une microfiche
  à l'autre → cards hétérogènes).
- Testé : `cover` 280×270 pour remplir la largeur → **rejeté** (rognait les miniatures).
- Les templates gardent un **commentaire** pour basculer facilement entre les deux sources.

## 3. Décisions structurantes (ne pas re-litiger)

| Sujet | Décision |
|---|---|
| Schéma d'URL | **id-based** (`{id}-{slug}`), pas slug-only |
| Partie cycle/moteur | **vrai niveau d'URL**, et niveau de breadcrumb après la moto |
| Pagination PLP | **aucune** — tout sur un écran |
| Produit hors stock | **pas d'ajout panier**, parcours alternatif à venir |
| Garage / sélecteur moto | **périmètre EveryParts**, on ne le câble pas |
| Powerparts filtrés moto | **via ukooparts** (Phase 2) — non filtrés pour l'instant |

## 4. Pièges connus (⚠️ à savoir avant de debugger)

1. **`ps_facetedsearch` capture les clics de filtre.** Son handler (dans `app.js`) fait un
   `stopImmediatePropagation()` en phase capture sur `#search_filters .facet-label`. **Ne jamais
   réutiliser ces sélecteurs** pour une UI de filtre custom → les nôtres sont découplés en
   classes `ms-plp-*`, avec un simple listener `change`.
2. **Le tri ne doit pas utiliser `js-search-link`** (déclencherait `fetchFacetUpdate` de
   facetedsearch). Nos items de tri sont en `js-ms-plp-sort`.
3. **Le hook `moduleRoutes` a nécessité une réinstallation du module.** L'auto-enregistrement
   ne se déclenche que sur une page du **vrai BO PrestaShop** (phpMyAdmin ne compte pas). Symptôme
   d'un hook non enregistré : **404 sur les URLs propres**. Notre `uninstall()` **ne droppe pas
   les tables** → réinstaller est sans risque pour les données.
4. **Le cache CCC est DÉSACTIVÉ en préprod.** Ne pas attribuer un bug au cache par réflexe.
   (En revanche la **table de routes** se purge bien via Vider le cache.)
5. **Exclusion des produits OEM** = `visibility = 'none'` **au niveau produit** (posé à l'import),
   **pas** une exclusion de catégorie dans le code. Conséquence : ils sont masqués de la home /
   recherche / suggestions, mais **restent accessibles** là où on les récupère **par id direct**
   (microfiches, bloc « produits liés »). ⚠️ Tout **nouvel import sans ce flag** les fera
   réapparaître partout.
6. **`available_for_order = 0`** (posé par un import) bloquait l'ajout au panier alors que le
   stock était bon — cause réelle d'un bug long à diagnostiquer. À vérifier sur les futurs imports.
